1

두 숫자의 관계

같이 움직인다는 것과, 원인이라는 것

1.1

상관계수 — 같이 움직이는 정도

상관계수가 클수록 점이 직선에 가깝게 모인다

+1 에 가깝다한쪽이 오르면 다른 쪽도 오른다
0 에 가깝다직선 관계가 약하다
−1 에 가깝다한쪽이 오르면 다른 쪽은 내린다
1.2

숫자만 보지 말고 그림도 봅니다

상관계수가 말해 주는 것

전체적으로 어느 쪽으로 기울어 있는지

말해 주지 않는 것

개별 값이 얼마나 흩어져 있는지
직선이 아닌 관계가 있는지

“할인율 30%인 주문의 이익은 얼마입니까?” — 약한 상관에서는 이 질문에 답할 수 없습니다. 전체 경향은 있어도 개별 건은 맞히지 못합니다.

같이 움직인다고 해서
한쪽이 다른 쪽의 원인인 것은
아닙니다
1.3

상관이 보일 때, 뒤에 있을 수 있는 것

왼쪽 — 같이 움직인다 · 오른쪽 — 제3의 원인이 있을 수 있다

순서가 반대 이익이 할인을 부른 것 — 안 팔리는 품목이라 할인을 했다
숨은 원인 제3의 것이 둘을 함께 움직임 — 재고가 오래돼 할인도 하고 이익도 낮다
1.4

그럼 인과는 어떻게 아는가

다른 조건은 같게 두고 한 가지만 바꿔 봐야 합니다.

A/B 테스트

들어오는 주문을 무작위로 두 무리로 나누고 한쪽만 할인합니다. 무작위로 나눴으니 지역도 품목도 양쪽에 골고루 섞입니다. 두 무리의 유일한 차이는 우리가 바꾼 것 하나뿐입니다.

가지고 있는 데이터를 들여다보는 것만으로는 여기까지 갈 수 없습니다. 그래서 보고서에는 “관계가 있다”까지만 적고, 원인은 실험으로 확인하겠다고 씁니다.

2

분석 에이전트 만들기

질문을 던지면 코드를 써서 답하는 도구

2.1

에이전트란 무엇인가

에이전트 = LLM + 하니스(harness)

LLM 에 무엇을 붙이느냐가 에이전트의 성능을 정한다

LLM 혼자서는 읽지도, 계산하지도, 저장하지도 못합니다.

2.2

오늘 만드는 것의 흐름

질문 → 구조 전달 → 코드 생성 → 실행 → 결과

회사 데이터는 못 보냅니다. 그래서 열 이름과 자료형만 보냅니다.

에이전트는
코드를 대신 써 줍니다

판단을 대신해 주지는 않습니다
2.6

데이터를 정말 못 보낼 때는
